II. What actually got fixed

1 · Full bleed, for real, not just in the doc pipeline/assemble_film.py's look() filter chain and card_png() both drew the old 36px inset + 5px stroke frame on every single shot. Both rewritten: no inset, no pad, no drawbox. The dead INSET/STROKE constants were removed rather than left to rot. The doc-generating HOUSE dict in shotlist_hemsworth.py was updated to match and the doc regenerated clean.
2 · The wrong-footage bug, found and fixed Root cause: assemble_film.py's own docstring says "generation is never used here" — there was no branch for GEN-S/GEN-V rows at all. They fell into the same generic footage-pool fallback as everything else, and that pool sorts hero windows first — one of which is CENTR.mp4 (workout footage). Row 2.01 ("a doctor sat down…holding a piece of paper") is early in the shot list, so it got first pick. Fixed by excluding GEN-S/GEN-V from that fallback; they now land on the existing text-card path instead of stealing unrelated footage. Not a full fix — until the assembler is taught to look up a real generated clip per row (see §III), these rows show a text card, not the intended picture. Honest, not wrong, which is the improvement.
3 · SFX layer built, sourcing pattern corrected The original directive assumed a Pixabay SFX API mirroring the Pexels b-roll pattern. No such API exists — Pixabay documents Images and Videos endpoints only. Rather than invent an integration, pipeline/sfx.py matches how library/music/ actually works today: manually downloaded, hand-catalogued in a JSON ledger. Enforces R11 (accent cap) and R12 (logged licence/attribution) in code, not just as a written rule.
4 · Inventory and gates, built and actually run inventory.py transcribed the 2 genuinely uncaptioned sources (a third, CENTRPOWER, turned out silent — confirms it's a trailer stinger, not a session) and indexed all 12. The gates/ suite wraps qc_render.py and shotlist_hemsworth.py's existing checks rather than reimplementing them, and in doing so fixed a bug that would have broken forever: its own frame gate still tested for the old inset signature, which the full-bleed fix would have failed on every future correct render. Validated against HEMSWORTH_V7_review.mp4: 13 of 29 gates pass, correctly convicted on the same known defects (12:58 runtime, 2.6s median hold, 18.2% real voice, 3 crowd shots).

III. The Veo batch — why it's paused

2.01 (consulting room) and 2.03 (boom mic) generated cleanly on the lite model — no reference image needed, $0.40 each, exactly as estimated. The problem is 2.04 and 12.03, which were designed to carry a shared reference image from 2.01 for pixel-consistency (the room, the report). The lite model rejects reference_images outright: "referenceImages isn't supported by this model."

The mistake

Finding the correct payload shape for the non-lite model took two live API probes. The first was rejected client-side (free). The second was accepted — and only then did it become clear the non-lite model bills at $0.40/second, not $0.05/s (that rate was lite-only). The accepted probe used a throwaway test prompt, not a real row, and cost $3.20 for nothing usable. That should have been checked before testing live, not after.

Finishing both remaining rows (2.04, 12.03) with the reference image, at the now-known correct rate, would cost $3.20 each — $6.40 more, landing the project at $10.44, over the project's own stated $10 ceiling. Paused here on the owner's explicit instruction, awaiting a decision between: both rows via the cheap lite model with no reference (prose-consistency only, $0.80 more); a mixed approach (reference for whichever row needs it more, roughly $3.60 more); both via the expensive model and accept going slightly over the ceiling; or leave these two rows unbuilt for now. No further spend happens until that call is made.

Separately, not blocking, but real Even once all 4 clips exist, assemble_film.py still doesn't know how to pick one up as a row's asset — the wrong-footage fix (§II.2) only stopped it from grabbing the wrong footage; it still falls back to a text card rather than a generated clip. That wiring hasn't been built.
